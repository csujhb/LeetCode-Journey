## 力扣 300：最长递增子序列 (C 语言) 学习笔记

### 1. 题目核心目标

在一个无序的整数数组中，找到**严格递增**的最长子序列的长度。
*注意：“子序列”不要求连续，只要相对顺序保持从左到右即可。*

### 2. 解法一：动态规划 (DP) - 稳扎稳打

这是最基础也最容易想到的解法。

* **状态定义**：`dp[i]` 表示以 `nums[i]` 这个数**结尾**的最长递增子序列的长度。
* **状态转移方程**：对于每个 `nums[i]`，我们需要回头看前面所有的 `nums[j]` ($j < i$)。如果 `nums[i] > nums[j]`，说明 `nums[i]` 可以接在 `nums[j]` 后面形成更长的递增子序列。
`dp[i] = max(dp[i], dp[j] + 1)`
* **复杂度**：时间复杂度 $O(N^2)$（两层嵌套 for 循环），空间复杂度 $O(N)$。

### 3. 解法二：贪心 + 二分查找 (Patience Sorting) - 降维打击

当数据量很大时，$O(N^2)$ 会超时。我们需要一种能让时间复杂度降到 $O(N \log N)$ 的方法，其核心思想来源于“耐心排序” (Patience Sorting) 扑克牌游戏。

#### 🌟 核心思维模型：扑克牌分堆

1. **贪心策略（越小越好）**：如果我们要让递增子序列尽可能的长，那么子序列的**结尾数字应该越小越好**。因为结尾数字越小，后面能接上来的数字就越多。
2. **牌堆规则**：
* 遍历数组，把每个数字看作一张扑克牌。
* 从左到右寻找第一个**牌堆顶的数字 $\ge$ 当前数字**的牌堆，把当前数字压在上面。（贪心：用更小的数字替换原来的堆顶，更有利于后续接牌）。
* 如果当前数字比所有牌堆顶的数字都大，那就**新建一个牌堆**放在最右边。


3. **终极结论**：**牌堆的总数量，就是最长递增子序列的长度！**

#### 🔍 为什么可以用二分查找？

因为根据我们的放牌规则，每次新建牌堆都是因为当前数字比前面的都大，所以**各个牌堆顶的数字，从左到右一定是严格递增的**。
既然“牌堆顶数组”（代码中的 `tails` 数组）是有序的，我们在寻找该放在哪个牌堆时，就可以直接使用**二分查找**，将查找时间从 $O(N)$ 降到 $O(\log N)$。

### 4. 最优解 $O(N \log N)$ 代码模板

```c
#include <stdlib.h>

int lengthOfLIS(int *nums, int numsSize) {
    if (numsSize == 0) return 0;

    // tails 数组存储每个牌堆顶的数字
    // tails[i] 表示长度为 i+1 的递增子序列的最小结尾数字
    int *tails = (int *)malloc(numsSize * sizeof(int));
    int len = 0; // len 表示当前牌堆的数量（即 LIS 的长度）

    for (int i = 0; i < numsSize; i++) {
        int x = nums[i];
        
        // 在 tails 数组中进行二分查找，寻找第一个 >= x 的牌堆
        int left = 0, right = len;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (tails[mid] < x) {
                left = mid + 1; // 目标在右半区
            } else {
                right = mid;    // 目标在左半区或就是 mid
            }
        }
        
        // 将当前数字 x 放到找到的牌堆顶（覆盖原值）
        tails[left] = x;
        
        // 如果 left == len，说明 x 比前面所有的牌堆顶都大，需要新建牌堆
        if (left == len) {
            len++;
        }
    }

    free(tails);
    return len; // 最终牌堆的数量就是最长递增子序列的长度
}

```

### 5. 复杂度终极对比

| 解法 | 时间复杂度 | 空间复杂度 | 适用场景 |
| --- | --- | --- | --- |
| **动态规划** | $O(N^2)$ | $O(N)$ | 数据量 $\le 10^3$，或者不仅要求长度，还要求打印出具体序列所有路径时。 |
| **贪心+二分** | $O(N \log N)$ | $O(N)$ | 数据量极大（$10^5$），只求长度的最优解。 |
